Alicorn is an **experimental native GUI runtime for Odin**. You describe your UI with ordinary
Odin code; the runtime retains identity, interaction, layout, text, and rendering products between
updates. Application data and policy stay in your own structs. The native host owns the window,
input pump, event loop, and GPU submission.

```odin
import ui "alicorn:ui"

App :: struct { saved: bool }

render :: proc(app: ^App, ctx: ^ui.UI) {
    if ui.column(ctx, padding = 24, gap = 12) {
        ui.text(ctx, "Hello, Alicorn")
        if ui.button(ctx, "Save") { app.saved = true }
    }
}

main :: proc() {
    app := App{}
    ui.run(&app, render, title = "Alicorn", width = 720, height = 480)
}
```

## Where AliKit fits

[AliKit](/components/) is the optional source-level component library for Alicorn. It adds
reusable behavior and copyable presentation over Alicorn's public APIs; it does not add a second
runtime, state store, theme engine, or component lifecycle. An application may use AliKit, copy a
single component, or build its own controls directly on Alicorn.

The dependency direction is one-way: application → AliKit (optional) → Alicorn.

## Project status

Alicorn is experimental and its API is evolving. The
[project status page](/docs/project/status/) records the current platform evidence and known
limits, and the [research index](/docs/research/) links the validation records behind those
claims. Read the [validated boundary](/docs/development/build-and-test/) before treating a
headless test as evidence about native window presentation or GPU output.
